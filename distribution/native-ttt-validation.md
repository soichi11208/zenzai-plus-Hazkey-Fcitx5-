# Native TTT検証（2026-10-19）

RTX 4070 SUPER（CUDA1）、zenzai-plusのFT済みGGUF F16で検証。
試験モデル・履歴・ソケットは `/tmp/hazkey-native-validation` に隔離した。
稼働中のIMEの入力履歴へ試験データは追加していない。

## 修正した不具合

- 各層の中間活性値が推論用の作業領域で上書きされていた。専用GPUバッファへ保持するよう修正。
- 交差エントロピーの勾配APIの引数順、最適化対象フラグ、LayerNormのスカラー展開を修正。

## 学習の効果

- 全12層の更新結果をCPUで計算した参照式と比較し、FP32重みの最大絶対誤差は0。
- 通常TTTを各1回適用した5例中4例で、指定表記の予測損失が改善した。

| 読み・表記 | 更新前の損失 | 更新後の損失 |
| --- | ---: | ---: |
| むそうかきょう → 夢想夏郷 | 2.82410 | 2.68068 |
| しょくもつせんい → 食物繊維 | 0.003736 | 0.002640 |
| さいきどう → 再起動 | 0.004511 | 0.004401 |
| せいしん → 精神 | 0.109761 | 0.117908 |
| ちゃんとうごいてる → ちゃんと動いてる | 0.000658 | 0.000589 |

損失は出力とEOSのトークン当たり負の対数尤度。小さいほど指定表記の確率が高い。
通常TTTを1回適用するだけでは「夢想夏郷」の貪欲生成には届かなかった。
明示的な単語登録では2回の更新で生成できた。

| 単語登録 | 更新回数 | モデル単体の生成 |
| --- | ---: | --- |
| 夢想夏郷 | 2 | 完全一致 |
| Codex猫 | 2 | 完全一致 |
| 空想回廊 | 0（元から生成可能） | 完全一致 |

Hazkey経由でも「無想か狂」が先頭だった候補から、登録後は「夢想夏郷」が先頭になった。

## 所要時間

| 処理 | 測定値 |
| --- | ---: |
| 通常TTTの更新 | 約6〜11ms |
| 単語登録の更新（C++単体、夢想夏郷） | 約4.7ms・2回 |
| 単語登録（Hazkey経由、初回） | 約34ms・2回 |
| 単語登録（Hazkey経由、2件目） | 約10ms・2回 |
| ネイティブ状態の保存 | 約115ms |
| 保存状態の復元 | 約47ms |
| 完成した重みの参照切り替え（C++単体） | 約0.037ms |
| 従来のHF更新＋保存＋GGUF変換（同じ4070 SUPER） | 約3,070ms |

更新＋保存は約0.13秒。入力確定から反映までは、従来からの2秒の待機と
タイマーの都合を含め、Hazkey経由の試験で約3〜4秒だった。
初回のモデル読み込みは上記の更新時間とは別。

## 学習中の入力・変換

実際のHazkeyプロトコルで「さいきどう」「しょくもつせんい」を交互に変換。
学習中の測定には保存処理も含む。試験時のモデルは読み込み済み。実環境と同じnico-pixiv通常辞書を含めた。

| 状態 | 件数 | 中央値 | 95パーセンタイル | 最大 |
| --- | ---: | ---: | ---: | ---: |
| 学習なし | 20 | 3.26ms | 3.59ms | 3.59ms |
| 学習・保存中 | 57 | 3.47ms | 4.10ms | 10.62ms |

軽い入力要求への応答も継続し、単語学習中の最大は約0.13ms。
別コンテキストで学習している間、推論側の重みが変化しないことを比較して確認した。
GPUを共有するため推論時間の変動はあるが、学習・保存の完了待ちはなかった。

推論と学習を含む隔離HazkeyプロセスのGPUメモリ使用量は、10ms間隔の観測で最大1,050MiB。
これはプロセス全体の値で、学習分だけの値ではない。

## 永続化と制限

- 保存・復元後も「夢想夏郷」をモデル単体で生成でき、処理済みカーソルも一致。
- 切れた保存ファイルと空の学習入力は拒否し、重みが変わらないことを確認。
- 通常TTTは全例の確率改善を保証しない（上の「精神」では損失が増えた）。
- 単語を続けて学習すると、後の更新で「Codex猫」が「codex猫」になる例があった。
  この逐次保持試験は3件中2件が完全一致。単語辞書に保存した表記とは別の、モデルの生成上の制限。
- 短い入力と少数の単語による機能・性能試験であり、あらゆる文章の品質や最大遅延の保証ではない。

詳細な数値は `native-ttt-validation.json`。

## 稼働環境への反映

上記の不具合修正をインストール済み。修正前のライブラリを退避し、Hazkeyサーバーを再起動した。
最終のHazkey経由試験は、インストール済みサーバーとライブラリを使って隔離環境で実施した。
